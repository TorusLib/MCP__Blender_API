## Быстрый старт (3 команды)

```cmd
BD_BASE\init.bat          ← настройка (1 раз)
BD_BASE\start_indexer.bat ← индексация (~10 мин)
start_mcp_server.bat      ← запуск HTTP сервера
```

### Что делает каждый скрипт

**`BD_BASE\init.bat`** — создаёт виртуальное окружение (`.venv`) и устанавливает все зависимости (`mcp`, `fastapi`, `beautifulsoup4`, `lxml`, `uvicorn`). Делается один раз при первом запуске или при переносе на новую машину. Если `.venv` уже существует — скрипт ничего не делает.

**`BD_BASE\start_indexer.bat`** — читает HTML-документацию из `API_DOC/` и создаёт/обновляет SQLite-базу данных в `BD_BASE/blender_api.db`. Первый запуск занимает ~10 минут, последующие — доли секунды (переиндексирует только изменённые файлы). Если вы обновили HTML-доки Blender — запустите этот скрипт.

**`start_mcp_server.bat`** — запускает HTTP REST-сервер на порту 18723. Сервер читает из базы данных и отвечает на запросы поиска. Если `.venv` не найден — сам запустит `init.bat`. Если база данных не найдена — выведет предупреждение. Доступ к API: [http://127.0.0.1:18723/docs](http://127.0.0.1:18723/docs).

Проще всего: **просто `start_mcp_server.bat`** — он сам создаст .venv, сам проиндексирует если нужно, сам запустит сервер.

## Все .bat-скрипты

| Скрипт | Когда | Что делает | Время |
|--------|-------|------------|-------|
| `start_mcp_server.bat` | Каждый раз | Запуск HTTP сервера (авто-.venv → авто-БД → авто-сервер) | ~1 сек |
| `BD_BASE\init.bat` | Один раз | Создаёт venv, ставит зависимости | ~15 сек |
| `BD_BASE\start_indexer.bat` | При обновлении HTML | Инкрементальная индексация | ~0.1 сек |
| `BD_BASE\start_indexer.bat --force` | Принудительно | Полная переиндексация всех файлов | ~10 мин |
| `BD_BASE\check_db.bat` | При подозрении | Сводка по версиям, MD5, даты | ~1 сек |
| `BD_BASE\force_reindex.bat` | БД сломалась | Удаляет БД и пересоздаёт | ~10 мин |

### Подробно о каждом

**`start_mcp_server.bat`** — главный скрипт. Проверяет наличие `.venv`, если нет — запускает `init.bat`. Затем запускает HTTP-сервер. Можно передать порт: `start_mcp_server.bat 8080`.

**`BD_BASE\init.bat`** — создаёт изолированное Python-окружение в папке `.venv` и устанавливает туда все зависимости из `requirements.txt`. После этого проект работает независимо от системного Python.

**`BD_BASE\start_indexer.bat`** — проверяет MD5-хэши HTML-файлов в `API_DOC/`, сравнивает с записями в базе, переиндексирует только изменившиеся. Если база не существует — создаёт её с нуля.

**`BD_BASE\start_indexer.bat --force`** — игнорирует MD5-хэши и переиндексирует абсолютно все файлы. Нужен если вы вручную меняли HTML-файлы или индексация завершилась с ошибкой.

**`BD_BASE\check_db.bat`** — выводит сводку: какие версии проиндексированы, сколько символов, когда последний раз индексировали, MD5-хэши файлов. Полезен для диагностики.

**`BD_BASE\force_reindex.bat`** — удаляет файл базы данных и запускает полную переиндексацию. Используйте только если база повреждена и обычные методы не помогают.

## Типичные сценарии

### Первый запуск
```cmd
BD_BASE\init.bat
BD_BASE\start_indexer.bat
start_mcp_server.bat
```

**Что происходит:** создаётся виртуальное окружение, устанавливаются зависимости, HTML-доки превращаются в базу данных, сервер запускается. После этого можно подключать Zed или обращаться к API.

### Ежедневная работа
```cmd
start_mcp_server.bat      ← сервер готов за 1 сек
```

**Что происходит:** скрипт проверяет `.venv`, запускает HTTP-сервер. База данных уже создана, ничего индексировать не нужно.

### Обновлённые доки Blender
```cmd
# Заменить HTML в API_DOC/
BD_BASE\check_db.bat      ← проверить расхождения
BD_BASE\start_indexer.bat ← пересоздать БД
start_mcp_server.bat      ← обновлённый сервер
```

**Что происходит:** вы скачали новые HTML-доки Blender, заменили файлы в `API_DOC/`. `check_db.bat` покажет, какие файлы изменились. `start_indexer.bat` обновит только изменённые файлы в базе. Сервер начнёт отдавать актуальные данные.

### БД сломалась
```cmd
BD_BASE\force_reindex.bat
```

**Что происходит:** база данных повреждена (например, крах при записи). Скрипт удаляет файл `blender_api.db` и создаёт его заново, переиндексируя все HTML-файлы. Занимает ~10 минут.

### Перенос на другую машину
```cmd
# Скопировать весь проект
start_mcp_server.bat      ← всё сделает сам
```

**Что происходит:** вы копируете папку проекта на другую машину (по сети, на флешке, через git). Запускаете `start_mcp_server.bat` — он сам создаст `.venv`, сам проиндексирует доки, сам запустит сервер. Ничего настраивать не нужно.

## Как скачать документацию Blender

Откройте https://docs.blender.org/api/current/index.html — там выбор всех версий.

1. Выберите нужную версию (3_6, 4_5, 5_1, ...)
2. Скачайте архив HTML-доков (ссылка на странице версии)
3. Распакуйте → найдите `docs/python_api`
4. Скопируйте содержимое в `API_DOC/X_Y/` (создайте папку, где X_Y — версия: `3_6`, `4_5`, `5_1`)
5. Запустите: `BD_BASE\start_indexer.bat`

**Важно:** в папке версии должны быть файлы `objects.inv` и `*.html`. Это стандартная структура Sphinx-документации Blender. Если вы скачали не тот архив — индексатор не найдёт файлы и выдаст ошибку.

## Подключение в Zed Editor

1. Убедитесь, что проект настроен: `BD_BASE\init.bat`
2. Откройте Zed → Settings (Command Palette → "Preferences: Open Settings (JSON)")
3. Добавьте в `context_servers` указав путь до папки ___ПУТЬ ДО ПАПКИ___ :

```json
"context_servers": {
    "Blender-API": {
        "enabled": true,
        "remote": false,
        "command": "___ПУТЬ ДО ПАПКИ___/.venv/Scripts/python.exe",
        "args": [
            "___ПУТЬ ДО ПАПКИ___/MCP__Blender_API/_mcp_server/server.py"
        ]
    }
},

```

    
> **Важно:** Используйте относительные пути (`_mcp_server/`, `.venv/`), а не абсолютные. Они работают на любой машине после клонирования репозитория.

4. Перезапустите Zed
5. Проверьте: в чате напишите `blender-api-docs: search for bpy.ops.mesh`

**Как это работает:** Zed запускает `server.py` как отдельный процесс и общается с ним через stdin/stdout. Сервер получает запросы, ищет в базе данных, возвращает результаты. Всё локально, без интернета.

**Если не работает:** откройте консоль Zed (View → Activity Bar → MCP), там будут видны ошибки запуска. Чаще всего проблема в неправильном пути к `python.exe`.

## Подключение в Cursor / Windsurf / другие MCP-клиенты

Аналогично — укажите путь к `_mcp_server/server.py` и установите `PYTHONPATH=_mcp_server`.

Настройка обычно находится в настройках MCP-клиента (часто в файле `settings.json` или через UI).

Пример для Cursor:
```json
{"mcpServers": {"blender-api-docs": {"command": "python", "args": ["_mcp_server/server.py"], "env": {"PYTHONPATH": "_mcp_server"}}}}
```

### MCP через HTTP (альтернатива)
Запустите: `start_mcp_server.bat` (запустит HTTP сервер)

Некоторые клиенты поддерживают подключение к MCP через HTTP вместо stdio. В этом случае укажите URL `http://127.0.0.1:18723`.

## Как добавить новые доки Blender

1. Откройте https://docs.blender.org/api/current/index.html
2. Выберите новую версию, скачайте архив доков
3. Распакуйте → скопируйте `docs/python_api` в `API_DOC/X_Y/`
4. Запустите: `BD_BASE\start_indexer.bat`

## Ручной запуск (без .bat)

```cmd
call .venv\Scripts\activate.bat
python _mcp_server\indexer.py
python _mcp_server\api_server.py
```

**Когда нужно:** если вы хотите запустить индексатор и сервер отдельно, или если батники по какой-то причине не работают.

**Порядок:** сначала `indexer.py` (создаёт базу), потом `api_server.py` (запускает сервер). Можно запускать в разных терминалах.

**Переменные окружения:** перед запуском нужно установить `PYTHONPATH=_mcp_server`, чтобы Python находил модули проекта.

## Портативность

- Все пути относительные, вычисляются от `config.py`
- `.venv/` — свой Python, свои пакеты
- Скопируй проект → запусти `start_mcp_server.bat` → готово
- Не требует установки Python в систему
- `.venv/`, `__pycache__/`, `*.db-wal`, `*.db-shm` — игнорируются git

**Что это значит:** вы можете сохранить проект на флешку, передать другу, клонировать с GitHub — на любой машине запустится одинаково. Не нужно ничего устанавливать в систему, всё живёт внутри папки проекта.

**Что не копируется:** база данных (`blender_api.db`) и HTML-доки (`API_DOC/`) не хранятся в git — они весят примерно 1.4 ГБ. Их нужно скачать отдельно (см. раздел «Как скачать документацию Blender»). Но после первого запуска `start_mcp_server.bat` всё создастся автоматически.

## Что умеет сервер

**HTTP REST API** (12 эндпоинтов):
- `GET /api/search?q=...` — поиск по имени/модулю
- `GET /api/symbol?name=...` — параметры, описания, дефолты
- `GET /api/module?module=...` — все символы в модуле
- `GET /api/page?uri=...` — контент HTML-страницы
- `GET /api/operators?q=...` — только `bpy.ops.*`
- `GET /api/types?q=...` — только `bpy.types.*`
- `GET /api/properties?q=...` — только `bpy.props.*`
- `GET /api/diff?symbol=...&v1=...&v2=...` — сравнить символ между версиями
- `GET /api/versions` — метаданные БД
- `GET /api/stats` — статистика
- `GET /api/cache-stats` — статистика кэша
- `POST /api/cache/clear` — очистить кэш (TTL 10 мин, LIMIT 500)

**Параметр `version`:** почти все запросы принимают параметр `version`. Значения:
- `latest` (по умолчанию) — последняя проиндексированная версия
- `all` — поиск по всем версиям сразу
- `3_6`, `4_5`, `5_1` — конкретная версия

**Параметр `limit`:** максимальное количество результатов (по умолчанию 20, максимум 200).

Для HTTP-API: [http://127.0.0.1:18723/docs](http://127.0.0.1:18723/docs) — Swagger UI (интерактивная документация, можно тестировать запросы прямо в браузере)

Чтобы запустить на другом порту: `start_mcp_server.bat 8080`
