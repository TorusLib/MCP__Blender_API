## ⚠️ Важное

**Без HTML-доков Blender проект не работает.** Без `API_DOC/` нет данных для поиска.

### Как добавить новые доки Blender

1. Скачать доки с нужной версией: https://docs.blender.org/api/current/index.html — распаковать в `API_DOC/X_Y/`
2. Выберите новую версию, скачайте архив доков
3. Распакуйте → скопируйте `docs/python_api` в `API_DOC/X_Y/`
4. Запустите: `BD_BASE\start_indexer.bat`

> This site can be used offline: Download the full documentation (zipped HTML files)

## Быстрый старт

```cmd
BD_BASE\init.bat          ← настройка (1 раз)
BD_BASE\start_indexer.bat ← индексация (~10 мин)
start_mcp_server.bat      ← запуск HTTP сервера
```

### Что делает каждый скрипт

**`BD_BASE\init.bat`** — создаёт виртуальное окружение (`.venv`) и устанавливает все зависимости (`mcp`, `fastapi`, `beautifulsoup4`, `lxml`, `uvicorn`). Делается один раз при первом запуске или при переносе на новую машину. Если `.venv` уже существует — скрипт ничего не делает.

**`BD_BASE\start_indexer.bat`** — читает HTML-документацию из `API_DOC/` и создаёт/обновляет SQLite-базу данных в `BD_BASE/blender_api.db`. Первый запуск занимает ~10 минут, последующие — доли секунды (переиндексирует только изменённые файлы). Если вы обновили HTML-доки Blender — запустите этот скрипт.

**`start_mcp_server.bat`** — запускает HTTP REST-сервер на порту 18723. Сервер читает из базы данных и отвечает на запросы поиска. Если `.venv` не найден — сам запустит `init.bat`. Если база данных не найдена — выведет предупреждение. Доступ к API: [http://127.0.0.1:18723/docs](http://127.0.0.1:18723/docs).

Проще всего: **просто `start_mcp_server.bat`** — он сам создаст .venv, сам проиндексирует если нужно, сам запустит сервер.

## Что умеет

10 MCP-инструментов + 12 HTTP REST-эндпоинтов: поиск по имени/модулю, детали символа, операторы (`bpy.ops`), типы (`bpy.types`), свойства (`bpy.props`), сравнение версий.

### Примеры запросов

| Что найти | Запрос |
|-----------|--------|
| Все операторы создания мешей | `search_operators("add mesh")` |
| Детали конкретного оператора | `get_symbol_details("bpy.ops.mesh.extrude_region_move")` |
| Все типы в модуле | `list_module("bpy.types")` |
| Сравнить тип между версиями | `diff_versions("bpy.types.Scene", "5_1", "4_5")` |
| Поиск по всему API | `search_symbol("material")` |

HTTP API: [http://127.0.0.1:18723/docs](http://127.0.0.1:18723/docs) — Swagger UI (интерактивная документация с возможностью тестировать запросы прямо в браузере)

## Режимы запуска

| Режим | Команда | Для чего |
|-------|---------|----------|
| HTTP (REST) | `start_mcp_server.bat` | Zed, Cursor, curl, WebUI (по умолчанию) |
| MCP (stdio) | `python _mcp_server/server.py` | Прямой запуск MCP-сервера для IDE |

**HTTP-режим** — сервер работает как отдельный процесс на порту 18723. К нему можно обращаться из любого клиента: браузера, curl, мобильных приложений, веб-интерфейсов.

**MCP-режим** — сервер работает внутри редактора (Zed, Cursor) через stdin/stdout. Не требует порта, не требует сети. Это основной режим для работы с AI-ассистентами.

## Стек

Python + SQLite (WAL) · MCP (FastMCP) · BS4 + lxml · Sphinx objects.inv

**Почему SQLite WAL:** режим Write-Ahead Logging позволяет читать базу одновременно с записью — сервер отвечает быстро даже во время индексации.

**Почему FTS5:** полнотекстовый индекс внутри SQLite — поиск работает без внешних зависимостей, быстро и без интернета.

**Почему инкрементальная индексация:** скрипт хранит MD5-хэши каждого HTML-файла. При повторном запуске проверяет хэши и переиндексирует только изменившиеся файлы — обычно за доли секунды.

## Портативность

Все батники используют **только** питон из `.venv/`. Никогда не трогают системный Python.

- Каждый скрипт определяет `VENV_PYTHON=%ROOT_DIR%\.venv\Scripts\python.exe`
- Все вызовы идут через `"%VENV_PYTHON%"`
- Скопируй проект → запусти `start_mcp_server.bat` → готово
